# CODE PURPLE MIP / PCA / BT / SIPOC bridge — V4.2

This file is a **projection and adapter**, not a new SSOT. The canonical architecture remains `docs/CODE_PURPLE_EXECUTION_GRAPH_ARCHITECTURE.md` and the existing viewer `docs/code_purple_execution_graph.html`, with `MIP/README.md` defining existing MIP lanes.

- **MIP-01–08:** stable evidence gate IDs, owner *roles*, priority and next proof. Runtime status is computed from source-bound observations; the JSON does not store a manually asserted PASS.
- **PCA-01–04:** require full observations, finite matrix with normalization and independence/stability checks. 2D GitHub timing PCA is *descriptive only*.
- **BT-01–04:** genuine independent matched test outcomes, >=30 distinct paired trials as a process heuristic, connected win graph, fit uncertainties and calibration. CI successes and failures are NOT pairwise comparisons.
- **SIPOC:** maps suppliers -> inputs -> process -> outputs -> consumers. Forward P1–P8 DAG contains no cycles; corrective feedback and predictive feedforward are separate overlays. CODEX orchestration, ABACUS execution evidence, and QPS engineering acceptance stay distinct.
- **Classification:** OBSERVED = evidence class has a bounded native observation, PARTIAL = incomplete proof, BLOCKED = a mandatory gate is presently not established, UNKNOWN = absent/unverified. These are not release scores.
