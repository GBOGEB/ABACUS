# CODE PURPLE / Office style input and testflight — source-owned candidate

**Status:** draft-only, observational, non-admitted. `authority_transfer=false`;
`security_waiver=false`; `merge_authorized=false`. No cross-repo dispatch.

## Objective

Use actual DOCX, XLSX and PPTX files as **input observations** for style,
layout and format generation without copying Office binary evidence into public
Git or confusing formatting with authoritative technical/project content.

`tools/office_style_probe.py` extends the **existing**
[`tools/qps_binary_bridge.py`](../tools/qps_binary_bridge.py) without changing
its original semantic extractor, SSOT, or child-QPS authority. The existing
binary bridge remains the source for content/anchor/semantic extraction;
this style probe is its read-only orthogonal format evidence producer.

The input need not have been generated by this project: it can be any authorized,
non-encrypted native `.docx`, `.xlsx` or `.pptx` file satisfying the explicit
security limits. The three supplied samples are **valid Office binaries** built
with python-docx, openpyxl and PptxGenJS but contain only synthetic demonstration
content, not user documents or commercial QPS information.

## Boundaries

| Plane | Role | What it owns |
|---|---|---|
| ABACUS | read-only OOXML style probe, tests, exact-run telemetry and own CI | normalized style evidence (derived) |
| ABACUS `qps_binary_bridge.py` | existing semantic bridge | text/anchor/formula semantics |
| CODEX Mission Control | read-only GUI/coordination, currently stage-only dispatch | no ABACUS mutation authority |
| `pipeline-automation-hub` | public method/SIPOC/graph/producer reference | no binary or source ownership transfer |
| QPS/source repository or evidence vault | originating file and permission decisions | source truth, confidential bytes |
| DOCX/PPTX/XLSX generating adapters | apply only approved style and source data to generated outputs | new derived artifacts |

**Do not commit** Office binary files, confidential originals or project-specific
review copies to `GBOGEB/ABACUS`. Its current QPS round-trip README explicitly
forbids generated `.docx`, `.xlsx`, `.pptx` and other binary outputs in public Git.
Store generated examples as local/CI artifacts with full SHA-256 and source
metadata. A public repo links to a sanitized manifest, never the input bytes.

## Run against a real Office source

```bash
python -m tools.office_style_probe ./authorized_review.docx \
  --source-id authorized-style-docx-v1 --out ./derived/docx.style.json
python -m tools.office_style_probe ./authorized_review.xlsx \
  --source-id authorized-style-xlsx-v1 --out ./derived/xlsx.style.json
python -m tools.office_style_probe ./authorized_review.pptx \
  --source-id authorized-style-pptx-v1 --out ./derived/pptx.style.json
```

The probe fails closed on unsupported extensions, malformed or damaged archives,
missing structural parts, member duplication, path traversal, symlinks, embedded
active content, suspicious ZIP inflation and external OOXML relationships.
No network calls or archive extraction are performed. Text, values, formulas,
speaker notes, source paths and sheet names are not included in the style JSON.

Derived JSON contains `source_id`, exact **input byte** `source_sha256`,
`style_fingerprint`, `extraction_quality`, format-specific `style_profile` and
explicit non-authority/UNKNOWN flags. The profile includes:

| Family | Observed style/format fields |
|---|---|
| DOCX | named heading/paragraph styles, font/color/size overrides, bold/italic counts, page/margin units, table count, theme font/color scheme |
| XLSX | sheet index and safe structural counts, cell-style/font/fill/border IDs, custom number formats, formulas by count only, merge/conditional/data validation counts, tables/charts, theme |
| PPTX | slide size and aspect, slide order, shape/text/image/chart/table/notes counts, used fonts/colors/sizes, master count, theme |

`style_fingerprint` is content-minimized and stable under *text-only edits that
preserve observed formatting*, not proof of full binary or layout equivalence.
Two templates with identical measured styles may have important unmeasured
rendering differences. Visual QA remains mandatory for generated Office outputs.

## Generate real example inputs (optional generator dependencies)

```bash
# Requires python-docx, openpyxl and Node.js with PptxGenJS.
python tools/build_office_style_examples.py --out ./build/office-fixtures
python tools/office_style_probe.py ./build/office-fixtures/CODE_PURPLE_Office_Style_Sample.pptx \
  --source-id demo-pptx --out ./build/office-fixtures/pptx.style.json
```

The generator writes three native binary files, SHA256 manifest and no
confidential content. DOCX uses actual Word paragraph styles, header/footer and
a formatted table; XLSX uses formulas, number formats, Excel table, chart,
conditional formatting, frozen panes and a palette sheet; PPTX uses 16:9 slides,
text runs, palette swatches, shapes and speaker notes.

Optional visual QA on a compatible machine:

- DOCX: render pages and visually inspect.
- XLSX: open/render every sheet; verify formulas, chart and formats; Excel
  formula values may require recalculation on open.
- PPTX: render every slide and test for out-of-bounds and overlap.

Local preparation QA: one-page DOCX rendered, 3-slide PPTX rendered without
canvas overflow, workbook loaded with openpyxl (3 sheets, 4 formulas, 1 chart,
1 Excel table). The local environment's artifact-tool workbook recalculation
interface was unavailable; no false claim of cached Excel formula values.

## Native test obligations, reverse tests and quality envelope

```bash
python -m pytest -q tests/test_office_style_probe.py tests/test_mip_testflight_plan.py \
  --cov=tools.office_style_probe --cov=tools.mip_testflight_plan \
  --cov-branch --cov-report=term
```

The source-only tests use ZIP packages assembled in temporary directories so
CI does not depend on bundling Office binaries. They cover real OOXML structures
and negative/mutated cases; a second optional integration exercise opens three
native Office files created by the external generator.

Latest local preparation: 82 `pytest` test functions passed, plus 18 unittest
subtest iterations. Two source modules: 610 statements / 322 branch points,
combined measured 87% `pytest-cov` report (planner 85%, style probe 88%). This
is **local candidate** coverage, not main coverage and not an admitted PR delta.
No scanner/security/review gate was weakened to achieve these counts.

Testflight selection and DAG planning remain owned by `tools/mip_testflight_plan.py`.
It is an offline *recommendation* and fail-closed DAG, not a workflow scheduler,
GitHub Action dispatcher, CodeQL bypass, authorized worker or CI admission.
The default sequence is: exact source/policy/provenance preflight → focused tests
and negative tests → native OS/Python matrix → artifact and style proof →
format/security/governance independently → permitted human admission →
exact-main REX and recurrence. Parallel independent lanes must not be serialized
without dependency evidence. Never reuse stale greens as current-head proof.
