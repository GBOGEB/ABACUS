1. Outward-facing deliverables

These six are what actually leave the project — everything else in the working folder exists to build or QA one of these.

Full evaluation workbook SSOT

QPS_OFFER_Evaluation_FULL_v23.xlsx
Audience: contract/engineering team — the working file

The single source of truth. Scores all 50 OFFER items against all 722 RTM requirements using the 7-dimension weighted BT ranking method (Safety/Legal, Reliability, Performance, Functional, Quality/Verifiability, Lifecycle, Cost). Every other file on this page is a trim, export, or presentation slice of this one workbook — nothing is maintained separately.

27 sheets, including internal audit/handover/method-control tabs (CHANGELOG, DMAIC_AUDIT, WEIGHTS_METHOD, CODING_HANDOVER) that the LITE trim below deliberately drops.

Reviewer workbook trim

QPS_OFFER_Evaluation_LITE_v23.xlsx
Audience: external reviewers, board, anyone without full project context

A 19-sheet trim of the FULL workbook: ranking, crosswalk, workspace, quality checks, lookup tools, filter dashboard, cluster and taxonomy tabs — everything a reviewer needs to evaluate the ranking, none of the internal audit/method-reproduction scaffolding. Kept in lockstep with FULL every round; same 722 RTMs, same numbers, no separate maintenance.

HTML Navigator read-only browser

QPS_RTM_BT_Navigator_v21.html
Audience: anyone who wants to browse without opening Excel

Single self-contained HTML file — no server, no install, works offline in any browser. Mirrors the FULL workbook's ranking, lookup, filter dashboard, domain/cluster heatmaps, document outline and taxonomy views. Data is spliced in at build time from a JSON export of the live workbook, never hand-typed, so it cannot drift from the SSOT independently. Read-only by design: edits happen in the workbook, then this page is regenerated from it.

BT-method presentation deck

BT_Method_Evaluation_v12.pptx
Audience: presenting the ranking methodology itself

Explains the 7-dimension weighted Bradley-Terry-style ranking method used across the whole evaluation — how the weights work, why gate items get precedence, what a "Weighted S" score means. This is the deck for explaining how the ranking was built, not for presenting individual RTM/OFFER results. v12 added an explicit "honest ranking" slide (official gate-first rank vs pure weighted-S rank, side by side, gate colouring kept) plus a weight-scenario comparison and a granular OFFER cross-reference slide.

watch v7/v8 still have no saved build script (binary-only). v9/v11 changes ARE documented in SESSION_SSOT.yaml prose even where no script was saved; v6, v10, and v12 have real saved/re-runnable scripts. Partial improvement, not fully closed.

2. How they relate to each other

Read together: the FULL workbook is the only place data is ever entered or changed. The LITE workbook and the HTML Navigator are both generated from FULL — never edited independently, and both regenerate cleanly any time FULL changes (LITE via a Python build script that drops internal-only sheets; the Navigator via a JSON data export spliced into a reusable HTML template). The two PowerPoint decks are separate lineages with their own narrative content, not auto-generated from the workbook, which is why they're the two items flagged "watch" above — they need a human to carry forward whatever changed, not just a script re-run. The Taxonomy PDF is the odd one out: a point-in-time export that nobody has re-run since v7, which is why it's flagged stale rather than watch — the risk there isn't "undocumented," it's "possibly outdated."

5. Internal / working artifacts (not for outside distribution)

Listed for completeness and traceability — these are how the six deliverables above get built and checked, not something to hand to a reviewer.

Engineering handover

ENGINEERING_HANDOVER_SESSION.md

Narrative handover for whoever picks up this project next: what it is, how to regenerate anything, known bugs fixed, known gaps, session status.

Structured session SSOT

SESSION_SSOT.yaml

Machine-readable decision log, build-chain provenance, and done/pending/missing status — the source the handover markdown is written from.

Artifact registry

ARTIFACT_REGISTRY.json

Auto-generated inventory of every file in the working folder, grouped by version family. Regenerate with generate_artifact_registry.py — never hand-edited, so it can't go stale relative to what's actually on disk.

Build scripts

build_workbook_v23.py · build_workbook_slim_v23.py · export_nav_data.py · classify_all_rtms.py · infer_clusters.py · t0_taxonomy.py · fix_mtbf_rtm_numbers.py

The reproducible pipeline: each script's declared input version must match the prior script's output, chaining FULL_v(N-1) → FULL_vN → LITE_vN → Navigator_vN.

QA harnesses

qa_nav_v8*.py and similar

Playwright/LibreOffice/raw-XML QA scripts run before anything above ships — zero formula errors, zero console errors, zero dangling relationships, zero dimension/autofilter mismatches is the bar.
