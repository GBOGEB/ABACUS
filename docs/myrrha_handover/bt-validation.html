Alternative Ranking Models

♟ Elo Rating System

R'i = Ri + K(Sij - Eij), where Eij = 1 / (1 + 10(Rj-Ri)/400)

Similar to BT but simpler sequential updates. Used in chess rankings. K-factor controls sensitivity. Pros: Simple, interpretable, online updates. Cons: Order-dependent, no confidence intervals.

🎯 TrueSkill (Microsoft)

μi ± 3σi → skill range; update via message-passing on factor graph

Bayesian skill rating that explicitly models uncertainty (σ shrinks with more comparisons). Pros: Uncertainty quantification, handles sparse data. Cons: Complex implementation, harder to explain.

📊 Plackett-Luce Model

P(ranking) = ∏k θπ(k) / Σj≥k θπ(j)

Extension of BT to full ranked lists (not just pairwise). Pros: Handles partial rankings, more flexible. Cons: More complex MLE, needs ranked list data.

🔢 AHP (Analytic Hierarchy Process)

Aw = λmaxw; Consistency Ratio = CI/RI where CI = (λmax - n)/(n-1)

Eigenvector method on pairwise comparison matrix with consistency checking. Pros: Well-established, consistency validation. Cons: Scale issues, needs calibrated comparisons.

📋 Recommendation

Keep Bradley-Terry as default — good balance of accuracy (τ=0.87), interpretability, and implementation simplicity. The 97.5% Fisher CI provides adequate uncertainty quantification for engineering decisions.

Future enhancements:

  • Add Elo as simpler alternative (for quick comparisons without full MLE)
  • Consider Plackett-Luce if category-level ranked lists become available
  • Implement TrueSkill for scenarios with very sparse comparison data
